# План проекта `letter`

Открытый текстовый редактор для настольных ОС на Rust, который повторяет внешний вид, функции и совместимость с файлами Microsoft Word (2024 и более ранних версий).

Этот файл — главный документ для любой новой сессии (человека или нейросети). Прочитай его целиком, прежде чем писать код.

---

## 0. Контекст для новой сессии

- **Владелец:** Nikita (GitHub `bikhe`). Опыта программирования нет, работает один, весь код пишут нейросети. Общение на русском, объяснять простыми словами.
- **Платформы:** Windows, macOS, Linux. Веб-версия не нужна.
- **Конечная цель:** «абсолютная копия» Word. Реалистичная стратегия: идём слоями, после каждой задачи программа собирается, запускается и проверяется руками.
- **Юридическое ограничение:** интерфейс делаем *похожим* на Word (расположение, поведение, горячие клавиши), но **не копируем** иконки, логотипы, шрифты и тексты Microsoft. Иконки свои или из открытых наборов (например, Fluent UI System Icons под MIT, Lucide под ISC; проверять лицензию). Название продукта — `letter`.
- **Как брать задачу:** выбери первую незакрытую задачу `[ ]` в текущей фазе, у которой выполнены зависимости. Работай в отдельной ветке, открой PR, после слияния отметь задачу `[x]` в этом файле в том же PR.

### Правила для сессий

1. Один PR — одна задача (или несколько очень мелких из одной фазы).
2. `cargo build`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all --check` должны проходить. CI это проверяет (задача F0.3).
3. Новая функция без теста не принимается. Для форматов — тест «открыть → сохранить → открыть», сравнение модели.
4. Никаких `unwrap()` в коде чтения файлов: битый файл не должен ронять программу.
5. Публичные типы и функции документируются комментариями `///`.
6. Если решение спорное (новая крупная зависимость, смена архитектуры) — опиши варианты в PR и спроси владельца.
7. Обновляй раздел «Журнал решений» в конце файла, если приняли архитектурное решение.

## 1. Архитектура

Cargo workspace из нескольких крейтов (библиотек), чтобы части можно было разрабатывать и тестировать отдельно:

```
letter/
├── Cargo.toml              # workspace
├── crates/
│   ├── letter-model/       # модель документа: абзацы, фрагменты, стили, таблицы...
│   ├── letter-docx/        # чтение и запись .docx (OOXML)
│   ├── letter-doc/         # чтение старого .doc (позже)
│   ├── letter-rtf/         # RTF (позже)
│   ├── letter-layout/      # вёрстка: шрифты, строки, страницы
│   ├── letter-render/      # отрисовка свёрстанных страниц (экран, PDF, печать)
│   ├── letter-editor/      # курсор, выделение, команды, отмена/повтор
│   ├── letter-app/         # окно, лента, диалоги (egui/eframe), бинарник `letter`
│   └── letter-cli/         # консольная утилита для отладки (`dump`, `roundtrip`)
├── tests/fixtures/         # реальные .docx/.doc для тестов
└── plan.md
```

Поток данных: `файл → letter-docx → Document (model) → letter-layout → страницы → letter-render → экран`. Правки идут через `letter-editor` в виде команд над моделью, после чего вёрстка пересчитывается (сначала целиком, позже — инкрементально).

### Выбранные технологии

| Задача | Выбор | Почему |
|---|---|---|
| Окно и интерфейс | `eframe` / `egui` | Просто, кроссплатформенно, нейросети хорошо его знают |
| Разбор XML | `quick-xml` | Быстрый, потоковый |
| ZIP-контейнер .docx | `zip` | Стандарт |
| Шрифты и формы глифов | `fontdb`, `skrifa` / `swash`, `rustybuzz` | Поиск системных шрифтов, метрики, шейпинг |
| Разбиение строк | `unicode-linebreak`, `unicode-bidi`, `unicode-segmentation` | Правила Unicode |
| Переносы слов | `hyphenation` | Словари для ru/en |
| PDF | `krilla` или `printpdf` | Решить в задаче F6 |
| Картинки | `image`, `resvg` (SVG) | |
| Ошибки | `thiserror` (библиотеки), `anyhow` (приложение) | |
| Логи | `tracing` | |

Свой движок вёрстки обязателен: готовые текстовые движки не умеют страницы, колонтитулы, сноски и правила Word.

## Фаза 1. Модель документа и .docx (минимум)

Зависит от: Ф0.

- [x] **F1.1 Модель.** `Document { sections, styles, numbering, settings, ... }`, `Block = Paragraph | Table`, `Paragraph { props, runs }`, `Run { text, props }`. Свойства символа: шрифт, размер, жирный, курсив, подчёркивание, зачёркивание, цвет, выделение цветом, над/подстрочный. Свойства абзаца: выравнивание, отступы, интервалы до/после, межстрочный интервал, стиль. Единицы — твипы (1/20 пункта) как в Word, отдельный тип `Twips`.
- [x] **F1.2 Неизвестное содержимое.** Любой XML, который мы не понимаем, сохраняется «как есть» (`Unknown(raw xml)`) и записывается обратно. Это главный механизм совместимости: не теряем то, что ещё не поддерживаем.
- [x] **F1.3 Чтение .docx.** Распаковка, `[Content_Types].xml`, `_rels`, `word/document.xml`: абзацы, фрагменты, свойства из F1.1, разрывы строк, табуляции.
- [x] **F1.4 Стили.** `word/styles.xml`: стили абзацев и символов, наследование (`basedOn`), значения по умолчанию (`docDefaults`), тема (`theme1.xml`) для шрифтов темы. Функция «вычислить итоговые свойства» для любого фрагмента.
- [x] **F1.5 Запись .docx.** Сериализация модели обратно в корректный пакет; неизвестные части и отношения копируются без изменений.
- [x] **F1.6 Тест кругового прохода.** Для каждого файла из фикстур: открыть → сохранить → открыть, модели равны. Ручная проверка: сохранённый файл открывается в Word и LibreOffice без предупреждений. *(LibreOffice: все образцы после сохранения выглядят пиксель в пиксель как исходные. Word в облаке недоступен — проверку в Word делает владелец.)*
- [x] **F1.7 Свойства документа.** `docProps/core.xml` и `app.xml`: автор, даты, число слов.
- [x] **F1.8 Консольная утилита для отладки.** `letter-cli dump file.docx` печатает дерево модели; `letter-cli roundtrip in.docx out.docx`.

## Справочные материалы

- ECMA-376 (Office Open XML), части 1 и 4 — спецификация .docx.
- [MS-OI29500] — как Word на самом деле отклоняется от ECMA-376.
- [MS-DOC] — спецификация бинарного .doc.
- [MS-OFFCRYPTO] — шифрование документов.
- Исходники LibreOffice (`writerfilter`, `sw`) — как другие решали те же проблемы (лицензия MPL, код не копировать, только изучать поведение).
